# ตรวจผลและแก้กระดูก RGB MoCap ผ่าน Codex

MCP ชื่อ `rgbmocap` ใช้ Python ที่มากับโปรแกรมและเปิดหน้าต่างตรวจโปรเจกต์แยกเมื่อเรียกเครื่องมือครั้งแรก ให้บันทึกแล้วปิด RGB MoCap หน้าต่างปกติก่อน เพราะ launcher ใช้ตัวล็อกเดียวกันกับโปรแกรมและตัวอัปเดต

## ติดตั้งและเชื่อมต่อ

1. Clone fork นี้และรัน `install.cmd` ตาม [คู่มือติดตั้ง](../README.md#install-and-run)
2. เปิด PowerShell ในโฟลเดอร์ที่ clone มา แล้วลงทะเบียนด้วย Codex CLI

   ```powershell
   $repo = (Get-Location).Path
   codex mcp add rgbmocap -- (Join-Path $repo 'runtime\python.exe') -I -X utf8 -B (Join-Path $repo 'tools\rgbmocap_mcp.py')
   codex mcp get rgbmocap
   ```

3. บันทึกแล้วปิดหน้าต่าง RGB MoCap ปกติ และเปิดแชต Codex ใหม่เพื่อโหลดเครื่องมือ

เซิร์ฟเวอร์ MCP ทำงานผ่าน stdio บนเครื่อง Windows ที่ติดตั้งโปรแกรม การเชื่อมต่อใช้คำสั่งข้างบนและไม่ต้องใส่ URL หรือ API token หากย้ายโฟลเดอร์ ให้รัน `codex mcp remove rgbmocap` แล้วลงทะเบียนจากตำแหน่งใหม่

หลังลงทะเบียน MCP ให้เปิดแชต Codex ใหม่จากโปรเจกต์นี้ ตัวอย่างคำสั่งที่พิมพ์ในแชตได้

> ใช้ rgbmocap เปิดโปรเจกต์ที่ A:\งาน\ท่าเดิน\project.json ไปเฟรม 120 แล้วแสดงวิดีโอต้นฉบับและมุมมอง 3D จากเฟรมเดียวกัน

> เทียบภาพก่อนและหลัง Apply Correction ที่เฟรม 120 แล้วช่วยดูตำแหน่งเท้ากับพื้น

> ใช้ rgbmocap ส่งออกท่าที่บันทึกไว้จากเฟรม 40 ถึง 75 เป็น A:\Exports\Walk_Start.fbx

| เครื่องมือ | ผลลัพธ์ |
| --- | --- |
| `get_status` | โปรเจกต์ โมเดล เฟรมที่เลือก เฟรมที่แสดง และความพร้อมของภาพท่าทาง |
| `open_project` | เปิดโฟลเดอร์หรือ `project.json` จากพาธเต็มบนเครื่อง |
| `seek_frame` | ไปยังเฟรมบน Timeline โดยเริ่มนับจาก 1 และรอจนเฟรมถูกถอดรหัส |
| `select_frame_range` | ไฮไลต์ช่วงเฟรมบน Timeline ระบุ `frame_start` และ `frame_end` รวมต้นและท้าย เว้นทั้งคู่เพื่อล้างช่วงที่เลือก |
| `capture_view` | ภาพ PNG ของ `viewport`, `video` หรือ `workspace` |
| `compare_motion` | ภาพจากเฟรมเดียวกันก่อนและหลังแก้ ใช้กล้องเดียวกันแล้วคืนเฟรมและผลที่เลือกไว้ |
| `export_fbx` | ส่งออกท่าที่บันทึกไว้เป็น FBX ระบุ `frame_start` และ `frame_end` เพื่อเลือกช่วงบน Timeline รวมเฟรมต้นและเฟรมท้าย หรือเว้นทั้งคู่เพื่อส่งออกเต็มช่วง |

การเปรียบเทียบอาศัยผลเดิมและผล Apply Correction ที่บันทึกแล้ว พร้อมข้อมูล 3D ที่เรนเดอร์ได้ ถ้าโปรเจกต์แจ้งว่าผลเก่าหรือขาด preview ให้เตรียมผลในหน้าต่าง RGB MoCap ปกติก่อน

`export_fbx` ใช้ผลปัจจุบันของคนในหน้าต่างตรวจโปรเจกต์ หรือผล Retarget ที่บันทึกไว้ถ้าระบุ `character_name` ปลายทางต้องเป็นพาธเต็มของไฟล์ใหม่ `.fbx` ในโฟลเดอร์ที่มีอยู่และอยู่นอกข้อมูลโครงการ ถ้าช่วงที่เลือกครอบคลุมหลายเทกของตัวละคร ให้เลือกช่วงที่อยู่ในเทกเดียวเพื่อส่งออกทีละไฟล์ การสร้างท่าจากวิดีโอใหม่ทำในหน้าต่าง RGB MoCap ปกติ

หลัง `select_frame_range` ให้ส่ง `frame_start` และ `frame_end` เดียวกันเข้า `export_fbx` เพื่อส่งออกช่วงที่ไฮไลต์ การเรียก `export_fbx` โดยเว้นทั้งคู่ใช้เต็มเทกเสมอ

## ดูต้นทางและแก้กระดูกผ่าน MCP

`bone_editor_status` แสดงเป้าหมายทั้งบุคคลต้นทางและตัวละครที่นำเข้า เช่น `source:1` คือ Person 1 ในโครงการที่มี ID นี้ ใช้ `select_motion_target` เพื่อดูเฉพาะเป้าหมายในมุมมอง 3D แล้วใช้ `list_bones` และ `get_bone_pose` อ่านตำแหน่งกับท่าที่บันทึกไว้ โครงที่มีเฉพาะตำแหน่งจะคืน `world_matrix: null` การเพิ่มคีย์หรือแก้ท่าใช้ ID ของตัวละครที่ Retarget แล้ว

Bone Editor ใช้กับตัวละครที่นำเข้าและ Retarget แล้ว เก็บการแก้เป็น layer แยกจากผล AI และแอนิเมชันฐาน ใช้ `get_status` อ่าน `characters[].id` และรายการ `takes` ก่อน เพื่อระบุตัวละครได้แน่นอนแม้ชื่อซ้ำกัน ถ้าเว้น `character_id` และ `take_index` เครื่องมือจะใช้ตัวละครและเทกที่เลือกใน Bone Editor

**เฟรมของเครื่องมือกระดูกเริ่มที่ 1 ภายในเทกตัวละคร** และ `take_index` เริ่มที่ 0 เช่น เทก 0 จำนวน 300 เฟรมใช้ `frame` 1–300 ส่วน `seek_frame`, `select_frame_range` และช่วงของ `export_fbx` ยังคงอ้างอิง Timeline หลัก เมื่อเทกเริ่มช้ากว่าวิดีโอหรือมีอัตราเฟรมต่างกัน เลขเฟรมสองแบบอาจไม่ตรงกัน

| เครื่องมือ | ผลลัพธ์ |
| --- | --- |
| `bone_editor_status` | อ่านตัวละคร เทก กระดูก เฟรม ชั้นแก้ไข และความพร้อม Undo/Redo โดยไม่เตรียม inference |
| `select_motion_target` | เลือกโครงบุคคลต้นทางหรือตัวละครที่ Retarget แล้วใน Bone Editor และมุมมอง 3D |
| `list_bones` | อ่านชื่อกระดูกทุกชิ้นและลำดับ parent; `prepare` ค่าเริ่มต้น `true` เตรียมแคชกระดูกครบชุดเมื่อจำเป็น โดยไม่จับท่าวิดีโอใหม่ |
| `select_bone` | เลือกกระดูกด้วยชื่อ `bone` และไฮไลต์ใน editor/viewport |
| `get_bone_pose` | อ่านท่าฐาน ท่าหลังแก้ และ offset ของกระดูก ณ `frame`; เว้นกระดูกหรือเฟรมเพื่อใช้ค่าที่เลือกอยู่ |
| `set_bone_keyframe` | เพิ่มหรือแทน keyframe ด้วย `bone`, `frame`, `translation`, `rotation`, `space` |
| `delete_bone_keyframe` | ลบ key ของ `bone` ที่ `frame` |
| `move_bone_keyframe` | ย้าย key จาก `frame` ไป `new_frame` |
| `set_bone_range` | ใช้ offset กับช่วง `frame_start`–`frame_end` รวมต้นและท้าย และรักษาค่าเดิมนอกช่วง |
| `set_bone_layer_enabled` | เปิด/ปิดการใช้ layer ด้วย `enabled`; preview และ FBX ตัวละครใช้สถานะเดียวกัน |
| `bone_editor_history` | ส่ง `action: "undo"` หรือ `"redo"` เพื่อย้อนหรือทำซ้ำการแก้ใน session นี้ |
| `clear_bone_track` | ลบ offset keys ของกระดูกหนึ่งชิ้น โดยเก็บแอนิเมชันฐานไว้ |
| `save_bone_edits` | บันทึก layer ของเทกที่เลือกไว้ในโครงการ |

`translation` เป็น `[X,Y,Z]` หน่วยเมตร และ `rotation` เป็น `[X,Y,Z]` องศา Euler XYZ ทั้งคู่เป็น **ค่า offset** ค่าเริ่มต้นเป็นศูนย์ `space` เลือก `local` หรือ `world` โดย world หมายถึงแกนฉากของตัวละครและหมุนรอบจุดกระดูก การแก้ frame/range จะ interpolate ตามคีย์ใน layer; ถ้าต้องการแก้เฉพาะช่วงให้ใช้ `set_bone_range` แทน key เดี่ยว

ตัวอย่างลำดับงานของ AI

1. `open_project` แล้ว `get_status` เพื่อเลือก `character_id` และเทก
2. `list_bones` ด้วย ID และ `take_index: 0` แล้วเลือกชื่อกระดูกจริง
3. `get_bone_pose` ที่เฟรมเป้าหมายก่อนแก้
4. เรียก `set_bone_keyframe` หรือ `set_bone_range` ด้วย offset ขนาดเล็ก จากนั้นใช้ `capture_view` ตรวจภาพ และ Undo ถ้าผลไม่เหมาะสม
5. `save_bone_edits` แล้ว `export_fbx` พร้อม `character_id` หรือ `character_name` เพื่อส่งออกแอนิเมชันตัวละครที่รวม layer ที่เปิดใช้อยู่

เครื่องมือกระดูกไม่มีคำสั่งรันโค้ดอิสระหรือสร้าง inference และไม่ใช้กับกระดูก SMPL ต้นทางโดยตรง การเตรียมครั้งแรกอาจใช้เวลานานกว่าการเลื่อนเฟรม เนื่องจากต้องสร้างแคชกระดูกครบทุกชิ้นจากไฟล์ Blender ที่บันทึกไว้ layer ผูกกับแอนิเมชันฐานของเทกนั้น การ Retarget ใหม่ต้องตรวจหรือสร้าง layer ให้ตรงฐานใหม่ ห้ามนำการแก้เก่าไปทับฐานใหม่โดยอัตโนมัติ

## คลังตัวอย่างการเคลื่อนไหว

| เครื่องมือ | ทำอะไรได้ |
| --- | --- |
| `analyze_motion_range` | สรุปช่วง 1–600 เฟรมของเทกที่เลือก วัดระยะ ความเร็ว และมุมงอของข้อต่อ ตัวละครที่เปิดชั้นแก้ไขจะมีผลก่อนแก้ให้เทียบด้วย |
| `remember_motion_example` | บันทึกช่วงที่ผู้ใช้เลือกให้จำ พร้อม `label` และ `note` เช่น คำอธิบายว่าต้องการคงไหล่ต่ำขณะยกแขน |
| `search_motion_examples` | ค้นจากชื่อ โน้ต ตัวละคร หรือชื่อกระดูก ใส่ `include_other_projects: true` เพื่อค้นเพิ่มในโปรเจกต์บนเครื่องใต้โฟลเดอร์ `projects/` |
| `forget_motion_example` | ลบตัวอย่างในโปรเจกต์ปัจจุบันด้วย `example_id` |

ให้ AI วิเคราะห์ช่วงก่อน จากนั้นบันทึกตัวอย่างที่เลือก และค้นตัวอย่างก่อนเสนอการแก้ในคลิปใหม่ ค่าใน `motion-memory.json` เป็นข้อมูลสรุปจากตำแหน่งกระดูกและโน้ตที่ช่วยอธิบายท่า ใช้ประเมินการขยับของข้อต่อได้ การวัดสัญญาณกล้ามเนื้อหรือฝึกน้ำหนักโมเดลใหม่ต้องใช้ข้อมูลและระบบต่างหาก

เมื่ออัปเดต tools ให้เชื่อมต่อ MCP ใหม่หรือเปิดแชตใหม่เพื่อโหลด schema ล่าสุด หน้าต่าง inspection ใช้เครื่องมือ MCP สำหรับเลือกและแก้ชั้นกระดูก
